# ระบบจัดการร้านอาหาร (Flask)

เว็บแอปภาษาไทยสำหรับจัดการเมนู โต๊ะ ออเดอร์หน้าร้านและออนไลน์ หน้าครัว การชำระเงิน ใบเสร็จ และรายงานยอดขาย พัฒนาด้วย Python 3, Flask และ Jinja2

## เริ่มใช้งานบนเครื่อง

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

เปิด `http://127.0.0.1:5000` แล้วเข้าสู่ระบบด้วยบัญชีตัวอย่าง:

- ผู้ดูแลระบบ: `admin` / `admin1234`
- พนักงาน: `staff` / `staff1234`
- ลูกค้า: สมัครสมาชิกผ่านหน้าเว็บ (บัญชีใหม่มี role `customer`)

ลูกค้าสมัครด้วยชื่อผู้ใช้ อีเมล รหัสผ่าน และยืนยันรหัสผ่าน จากนั้นตรวจทานและกดยืนยันก่อนสร้างบัญชี พร้อมตั้งคำตอบกู้คืนผ่านคำถาม “คุณชอบอะไร?” (ยังไม่มีการส่งอีเมล OTP) ลืมรหัสผ่านได้โดยใช้ชื่อผู้ใช้/อีเมลและคำตอบนี้ ผู้ใช้ที่ล็อกอินแล้วเปลี่ยนรหัสผ่านได้จากเมนู “เปลี่ยนรหัสผ่าน” บัญชีผู้ดูแลและพนักงานใช้คำตอบกู้คืน `HelloWorld` (ระบบเก็บเป็น hash); เปลี่ยนคำตอบเองได้หลังล็อกอิน ลูกค้าเดิมที่ยังไม่มีคำตอบกู้คืนให้ล็อกอิน แล้วเข้า “เปลี่ยนรหัสผ่าน” เพื่อไปตั้งคำตอบก่อนใช้งานฟังก์ชันลืมรหัสผ่าน เข้าสู่ระบบได้ด้วยชื่อผู้ใช้หรืออีเมล ลูกค้าจองโต๊ะด้วยจำนวนคน ระบบจัดโต๊ะว่างให้ทันทีหรือเข้าคิวอัตโนมัติ และแสดงเมนูเมื่อได้นั่งแล้ว ลูกค้าเลือกหลายเมนูลงตะกร้า ปรับจำนวน แล้วกดยืนยันส่งออเดอร์ เลือกระดับความเผ็ด ขนาด และท็อปปิ้งได้โดยราคาเพิ่มจากที่ผู้ดูแลตั้งไว้ พนักงานและผู้ดูแลตั้งราคาตัวเลือกและแก้ชื่อ/ราคาเมนูได้ ผู้ดูแลแก้ชื่อร้าน วันและเวลาเปิด ข้อความประกาศ สี โลโก้อัปโหลด ภาพแบนเนอร์ รูปแบบการ์ด และเมนูแนะนำได้จาก “ตกแต่งหน้าร้าน” พร้อมดูตัวอย่างก่อนบันทึก

เปลี่ยนรหัสบัญชีตัวอย่างโดยกำหนด `RMS_ADMIN_PASSWORD` และ `RMS_STAFF_PASSWORD` ก่อนเริ่มแอป การตั้งค่านี้ใช้ตอนสร้างบัญชีครั้งแรกเท่านั้น เปลี่ยนชื่อบัญชีตัวอย่างได้ด้วย `RMS_ADMIN_USER` และ `RMS_STAFF_USER` กำหนด `SECRET_KEY` เป็นค่าสุ่มที่ยาวและคงที่สำหรับทุก deployment

## Deploy บน Vercel

โครงสร้าง `api/index.py`, `vercel.json` และ `requirements.txt` ตั้งค่าให้ Vercel Python Function เรียกแอป Flask แล้ว เชื่อม Git repository กับ Vercel และกำหนด Environment Variables อย่างน้อย:

- `SECRET_KEY`: ค่าสุ่มลับที่คงที่
- `RMS_ADMIN_PASSWORD`: รหัสผู้ดูแลระบบที่ปลอดภัย
- `RMS_STAFF_PASSWORD`: รหัสพนักงานที่ปลอดภัย
- `VERCEL=1` ถูกกำหนดโดยแพลตฟอร์ม

แนะนำให้ใช้ PostgreSQL สำหรับข้อมูลใช้งานจริง โดยสร้างฐานข้อมูล PostgreSQL ที่รองรับ SSL (เช่น Neon หรือบริการที่คุณเลือก) แล้วเพิ่ม Environment Variable `DATABASE_URL` เป็น connection string ของฐานข้อมูล จากนั้น redeploy แอป หากตั้งทั้ง PostgreSQL และ Upstash แอปจะใช้ PostgreSQL ก่อน ระบบสร้างตารางข้อมูลให้อัตโนมัติและตรวจ revision ทุกครั้งที่บันทึก เพื่อป้องกันการเขียนทับข้อมูลจากคำขอพร้อมกัน; เมื่อพบการแก้ไขชนกัน ระบบจะแจ้งให้โหลดหน้าใหม่และลองอีกครั้ง

ใช้งานบนเครื่องได้เลยโดยไม่ต้องตั้ง Upstash แอปจะบันทึกลง `data.json` ส่วนบน Vercel การล็อกอินเก็บตัวตนที่จำเป็นใน secure session cookie แล้ว แต่ข้อมูลบัญชี/ออเดอร์ยังต้องใช้พื้นที่เก็บข้อมูลถาวรเพื่อคงอยู่ข้าม instance แอปรองรับ [Upstash Redis REST API](https://upstash.com/docs/redis/features/restapi) โดยไม่เพิ่ม dependency ให้สร้างฐานข้อมูล Upstash แล้วกำหนด Environment Variables ต่อไปนี้:

- `UPSTASH_REDIS_REST_URL`: REST URL ของฐานข้อมูล
- `UPSTASH_REDIS_REST_TOKEN`: token ของฐานข้อมูล
- `RMS_REDIS_DATA_KEY` (ไม่บังคับ): Redis key; ค่าเริ่มต้น `restaurant-management:data`

เมื่อไม่มี `DATABASE_URL` แต่กำหนด Upstash URL และ token ครบ แอปจะใช้ Redis เก็บ JSON ทั้งชุด; ถ้าไม่กำหนดบริการใด แอปใช้ `data.json` ในเครื่อง และ `/tmp/restaurant-management-data.json` บน Vercel ซึ่งเป็นพื้นที่ชั่วคราวและอาจทำให้ข้อมูลหายเมื่อเปลี่ยน instance จึงอย่าใช้ file storage เป็นข้อมูลจริงบน Vercel

ผู้ดูแลระบบดาวน์โหลดสำเนาข้อมูลได้จาก “สำรองข้อมูล” บนแถบนำทาง ไฟล์นี้มีบัญชีผู้ใช้และข้อมูลระบบทั้งหมด จึงควรเก็บไว้อย่างปลอดภัยและไม่แชร์ต่อ การสำรองนี้เป็นแบบดาวน์โหลดด้วยผู้ดูแล; ควรเปิด automated backups/snapshots จากผู้ให้บริการ PostgreSQL เพิ่มด้วย

## ฟังก์ชันหลัก

- บัญชีและ role `admin`, `staff`, `customer`; มีหน้าทบทวนยืนยันสมัครสมาชิก รหัสผ่านจัดเก็บแบบ hash และฟอร์ม POST ใช้ CSRF token
- ลืมรหัสผ่านด้วยคำตอบกู้คืน, เปลี่ยนรหัสผ่านโดยตรวจรหัสเดิม, และตั้งคำตอบกู้คืนสำหรับบัญชีเดิม
- CRUD เมนูและโต๊ะ; ค้นหา กรอง เรียง และแบ่งหน้าเมนูได้
- ลูกค้าจองโต๊ะ/เข้าคิวตามจำนวนคน โต๊ะว่างจัดให้อัตโนมัติ และคิวถัดไปรับโต๊ะทันทีเมื่อ checkout
- ลูกค้าเลือกหลายเมนูใส่ตะกร้า ปรับจำนวนและยืนยันก่อนส่งร้าน พร้อมตัวเลือกเผ็ด/ขนาด/ท็อปปิ้งที่คำนวณราคาโดยเซิร์ฟเวอร์
- ลูกค้าดูตัวเลือกที่สั่งและเพิ่ม/ลดจำนวนต่อรายการก่อนครัวเริ่มทำ; KDS แสดงตัวเลือกให้ครัว
- ครัวอัปเดตสถานะรับออเดอร์ → กำลังทำ → พร้อมเสิร์ฟ → พนักงานเสิร์ฟถึงโต๊ะ → ลูกค้ายืนยันว่าได้รับอาหาร ก่อนส่งคำขอชำระเงิน; โต๊ะยังไม่ว่างจนกว่าพนักงานจะยืนยันรับชำระ
- ผู้ดูแลบังคับยกเลิกการใช้โต๊ะที่มีลูกค้านั่งได้ ระบบยกเลิกออเดอร์ที่ยังเปิด คืนสต็อกที่หัก และแจ้งลูกค้าที่ได้รับผลกระทบ
- แจ้งเตือนในเว็บเมื่อครัวเปลี่ยนสถานะ ได้โต๊ะแล้ว ร้านยืนยันชำระเงิน หรือการจองล่วงหน้าเปลี่ยนสถานะ
- กำหนดสต็อกเป็นจำนวนจานต่อเมนู; ระบบหักเมื่อส่งออเดอร์และคืนสต็อกเมื่อร้านยกเลิก
- จองล่วงหน้าตั้งแต่ 10 นาทีถึง 90 วัน พร้อมตรวจความจุช่วงเวลา และให้ร้านยืนยันหรือปฏิเสธ
- หน้าภาพรวมลูกค้าแสดงชื่อร้าน วัน/เวลาเปิด ข้อความตกแต่ง และเมนูแนะนำที่ผู้ดูแลเลือกได้
- ผู้ดูแลแก้ชื่อร้าน เวลาทำการ ข้อความหน้าร้าน และเมนูแนะนำ; ผู้ดูแล/พนักงานตั้งตัวเลือกและราคาเพิ่มรายเมนู
- เครื่องมือตกแต่งหน้าร้านแบบไม่ต้องแก้โค้ด: แก้ชื่อร้าน/วันและเวลาเปิด/ข้อความ สีหลัก/สีเน้น/พื้นหลัง โลโก้ ภาพปก ประกาศ รูปแบบการ์ด และเมนูแนะนำ พร้อมทางลัดไปแต่ละส่วนและตัวอย่างก่อนบันทึก
- เปิดออเดอร์ต่อโต๊ะ เพิ่ม/ลด/ยกเลิกรายการ ย้ายโต๊ะ และปรับสถานะครัวตามเวลา; ลูกค้าเห็นโต๊ะที่ได้รับในแถบนำทางและ checkout โต๊ะได้
- คำนวณส่วนลด ค่าบริการ และ VAT พร้อมใบเสร็จพิมพ์ได้
- Dashboard สรุปยอดขายวันนี้ เมนูขายดี และบันทึก audit trail
- ค้นหา/กรอง/เรียง/แบ่งหน้าในรายการเมนูและออเดอร์

## ไฟล์ข้อมูล

`sample_data.json` เป็นข้อมูลตั้งต้นสำหรับร้านใหม่ (เมนูและโต๊ะตัวอย่าง โดยไม่มีบัญชีลูกค้าหรือออเดอร์ส่วนตัว) หากยังไม่มีข้อมูล แอปจะคัดลอกชุดตั้งต้นเป็นสถานะเริ่มต้น สคีมาข้อมูลเก่าจะได้รับค่าเริ่มต้นสำหรับสต็อก การจองล่วงหน้า และการแจ้งเตือนโดยอัตโนมัติ บัญชีผู้ดูแล/พนักงานจะถูกสร้างเมื่อเริ่มแอปครั้งแรก เลือกที่เก็บข้อมูลตามลำดับ `DATABASE_URL` → Upstash Redis → ไฟล์ JSON ในเครื่อง
