# ระบบจัดการร้านอาหาร (Flask)

เว็บแอปภาษาไทยสำหรับจัดการเมนู โต๊ะ ออเดอร์หน้าร้านและออนไลน์ หน้าครัว การชำระเงิน ใบเสร็จ และรายงานยอดขาย พัฒนาด้วย Python 3, Flask และ Jinja2

## เริ่มใช้งานบนเครื่อง

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

เปิด `http://127.0.0.1:5000` แล้วเข้าสู่ระบบด้วยบัญชีตัวอย่าง:

- ผู้ดูแลระบบ: `admin` / `admin1234`
- พนักงาน: `staff` / `staff1234`
- ลูกค้า: สมัครสมาชิกผ่านหน้าเว็บ (บัญชีใหม่มี role `customer`)

ลูกค้าจะเห็นหน้ายืนยันก่อนสร้างบัญชี และสามารถสั่งอาหารออนไลน์ ดูจำนวนแต่ละเมนู เพิ่ม/ลดจานในออเดอร์ได้จนกว่าครัวเริ่มทำ พนักงานและผู้ดูแลแก้ชื่อ/ราคาเมนูได้ ส่วนผู้ดูแลเปลี่ยนชื่อร้านจาก “ตั้งค่าร้าน”

เปลี่ยนรหัสบัญชีตัวอย่างโดยกำหนด `RMS_ADMIN_PASSWORD` และ `RMS_STAFF_PASSWORD` ก่อนเริ่มแอป การตั้งค่านี้ใช้ตอนสร้างบัญชีครั้งแรกเท่านั้น เปลี่ยนชื่อบัญชีตัวอย่างได้ด้วย `RMS_ADMIN_USER` และ `RMS_STAFF_USER` กำหนด `SECRET_KEY` เป็นค่าสุ่มที่ยาวและคงที่สำหรับทุก deployment

## Deploy บน Vercel

โครงสร้าง `api/index.py`, `vercel.json` และ `requirements.txt` ตั้งค่าให้ Vercel Python Function เรียกแอป Flask แล้ว เชื่อม Git repository กับ Vercel และกำหนด Environment Variables อย่างน้อย:

- `SECRET_KEY`: ค่าสุ่มลับที่คงที่
- `RMS_ADMIN_PASSWORD`: รหัสผู้ดูแลระบบที่ปลอดภัย
- `RMS_STAFF_PASSWORD`: รหัสพนักงานที่ปลอดภัย
- `VERCEL=1` ถูกกำหนดโดยแพลตฟอร์ม

บน Vercel ต้องใช้พื้นที่เก็บข้อมูลถาวรเพื่อให้การสมัครและออเดอร์ยังอยู่ระหว่างคำขอคนละ instance แอปรองรับ [Upstash Redis REST API](https://upstash.com/docs/redis/features/restapi) โดยไม่เพิ่ม dependency ให้สร้างฐานข้อมูล Upstash แล้วกำหนด Environment Variables ต่อไปนี้:

- `UPSTASH_REDIS_REST_URL`: REST URL ของฐานข้อมูล
- `UPSTASH_REDIS_REST_TOKEN`: token ของฐานข้อมูล
- `RMS_REDIS_DATA_KEY` (ไม่บังคับ): Redis key; ค่าเริ่มต้น `restaurant-management:data`

เมื่อกำหนด URL และ token ครบ แอปจะเก็บ JSON ทั้งชุดใน Redis; ถ้าไม่กำหนด แอปใช้ `data.json` ในเครื่อง และใช้ `/tmp/restaurant-management-data.json` บน Vercel ซึ่งเป็นพื้นที่ชั่วคราวและอาจทำให้ข้อมูลหายเมื่อเปลี่ยน instance จึงควรกำหนด Upstash ก่อนเปิดให้ลูกค้าสมัครหรือสั่งจริง การเก็บทั้งชุดเป็น JSON key เหมาะกับร้านขนาดเล็ก/เดโม; ระบบที่มีคำขอพร้อมกันมากควรย้ายไปฐานข้อมูลเชิงสัมพันธ์

## ฟังก์ชันหลัก

- บัญชีและ role `admin`, `staff`, `customer`; มีหน้าทบทวนยืนยันสมัครสมาชิก รหัสผ่านจัดเก็บแบบ hash และฟอร์ม POST ใช้ CSRF token
- CRUD เมนูและโต๊ะ; ค้นหา กรอง เรียง และแบ่งหน้าเมนูได้
- ลูกค้าสั่งอาหารออนไลน์และดูออเดอร์ของตนเอง พร้อมเพิ่ม/ลดจำนวนก่อนครัวเริ่มทำ
- เปลี่ยนชื่อร้านได้จากหน้าตั้งค่า; แก้ชื่อและราคาอาหารจากหน้าเมนู
- เปิดออเดอร์ต่อโต๊ะ เพิ่ม/ลด/ยกเลิกรายการ ย้ายโต๊ะ และปรับสถานะครัวตามเวลา
- คำนวณส่วนลด ค่าบริการ และ VAT พร้อมใบเสร็จพิมพ์ได้
- Dashboard สรุปยอดขายวันนี้ เมนูขายดี และบันทึก audit trail
- ค้นหา/กรอง/เรียง/แบ่งหน้าในรายการเมนูและออเดอร์

## ไฟล์ข้อมูล

`data.json` เป็นชุดข้อมูลตั้งต้นสำหรับการพัฒนา โดยมีเมนูและโต๊ะตัวอย่าง บัญชีผู้ดูแล/พนักงานจะถูกสร้างอัตโนมัติเมื่อเริ่มแอปครั้งแรก และข้อมูลที่แก้ไขจะถูกเขียนกลับไปยังไฟล์ JSON ที่กำหนดด้วย `RMS_DATA_FILE` (ค่าเริ่มต้นในเครื่องคือ `data.json`) หากกำหนด Upstash URL และ token แอปจะใช้ Redis แทนไฟล์
